# AdventureWorks2012 SQL Server Analysis

A portfolio project based on Microsoft's AdventureWorks2012 sample database. It demonstrates SQL Server relational queries, contact-data joins, sales filtering, aggregation, monthly analysis, and window functions.

## Project objectives
- Restore the official `AdventureWorks2012` sample database in SQL Server.
- Retrieve person contact details including email, phone number and phone number type.
- Retrieve sales orders and line-item details for July 2005, the first month in this database.
- Calculate total sales for July 2005.
- Calculate 2006 sales totals by month and sort by sales amount.
- Calculate month-on-month sales change for 2006 using `LAG()`.
- Calculate total sales associated with customer Gustavo Achong.

## Technologies
- Microsoft SQL Server
- SQL Server Management Studio (SSMS)
- T-SQL

## SQL concepts
`SELECT`, `WHERE`, `INNER JOIN`, `LEFT JOIN`, `GROUP BY`, `ORDER BY`, `SUM()`, date-range filtering, CTEs, `DATEFROMPARTS()`, and `LAG()`.

## Automated validation
GitHub Actions runs SQLFluff's T-SQL parser and a separate temporary SQL Server Developer container. The execution workflow downloads and restores Microsoft's official AdventureWorks2012 backup, checks the data date range, executes all seven queries, uploads the output as a 14-day artifact, and removes the SQL Server container. This is a real execution against the official sample database, not just parser validation.

## Run the project against the real database
1. Download the official AdventureWorks2012 backup from Microsoft's SQL Server samples.
2. Restore `AdventureWorks2012.bak` in SQL Server Management Studio.
3. Open `AdventureWorks2012_Analysis.sql` and execute it against the restored database.
4. Review the result sets and save screenshots only after they are generated by SQL Server.

Official sample database: https://github.com/Microsoft/sql-server-samples/releases/tag/adventureworks

## Dataset date-range correction
The official AdventureWorks2012 backup contains 31,465 sales orders dated from 2005-07-01 through 2008-07-31. It contains no May 2011 sales orders. The earlier 2011 filters therefore returned empty sales result sets. To produce meaningful, verifiable analysis, the project now uses July 2005 for the monthly order/detail/total queries and calendar year 2006 for monthly and month-on-month analysis. This change is based on the restored database's actual date coverage.

## Accuracy note
Numeric results are generated by SQL Server in the GitHub Actions run artifact; they are not fabricated. The synthetic fixture is separate test scaffolding and is not used as a substitute for the official AdventureWorks dataset.
